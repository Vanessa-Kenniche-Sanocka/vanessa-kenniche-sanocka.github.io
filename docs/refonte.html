Refonte du CV — Spécifications détaillées

Document de référence pour refaire le site CV à partir de zéro (base Quarto + 3 langues EN/FR/PL). Résume l’intention esthétique, le système de design, les choix techniques, les pièges à éviter.

1. Intention et vocabulaire esthétique

L’ambiance recherchée

On vise l’esthétique des sites personnels de gens très seniors : avocats d’affaires, chercheurs dans de grandes institutions, architectes établis, consultants indépendants haut de gamme. Pas une landing page de startup, pas un template SaaS, pas un portfolio de designer flashy. Quelque chose qui respire l’établi, le sérieux, la maturité professionnelle.

Mots-clés pour verbaliser cette direction :

  • Éditorial — la mise en page rappelle un magazine imprimé de qualité (Monocle, The Economist, Apollo), avec une typographie soignée, un rythme de lecture confortable, de l’air autour du texte
  • Glassmorphism discret — l’effet “verre dépoli” mais subtil, pas le cliché Big Sur bleu pétant. Un flou léger (backdrop-filter: blur(20-22px)), une opacité de 80-85% sur les cartes, un voile saturé qui laisse respirer le fond sans le noyer
  • Floating / weightless — les blocs de contenu donnent l’impression de flotter au-dessus d’un décor : cartes avec coins doux (14-20px), ombres étagées douces (jamais de drop-shadow brutal), pas de bordures dures
  • Corporate moderne — inspirations type Stripe, Linear, Vercel, Notion — mais dépouillé de leur côté tech, tiré vers quelque chose de plus feutré
  • Precision — marges, paddings et tailles de polices ajustés avec soin, tout sur une échelle de 0.25rem (4px), rien au pif
  • Prestige silencieux — pas de dégradés criards, pas d’animations qui distraient, pas d’emojis, pas de gradients violets. Le raffinement se sent dans les détails : la graisse exacte d’un titre, l’espace entre deux tags, la courbe d’easing d’un hover

Ce qu’on évite absolument

  • Templates bootstrap-y avec leurs cartes carrées et leurs boutons carrés
  • Effets neon, glow, gradient animé, parallax exagéré
  • Skeuomorphism (ombres 3D, textures)
  • Emojis décoratifs dans le contenu
  • Animations qui rebondissent (bounce, elastic)
  • “Check out my work!” énergétique / marketing
  • Polices trop signées (Pacifico, Dancing Script, etc.)
  • Couleurs chaudes saturées (orange vif, rose flashy)

Références visuelles à regarder

Pour caler l’œil : sites personnels de Jony Ive, Craig Mod, Robin Rendle, Nat Friedman, Patrick Collison, certains portfolios de consultants ou d’architectes sur Squarespace premium. Magazines en ligne : The New Yorker (mais en moins serif), Aeon, Works in Progress.

2. Palette de couleurs

Le site doit avoir deux thèmes complets (clair + sombre), pilotés par l’attribut HTML data-theme et une persistance localStorage.

Mode clair — neutre crème, pas blanc pur

Surface élevée (hover)          rgba(255, 255, 255, 0.94)

Mode sombre — noir bleuté, jamais noir pur

Overlay de fond (voile)         rgba(8, 10, 16, 0.70)

Texte secondaire                #c4c6cc

Règles importantes

  • Jamais de blanc pur (#fff) ni de noir pur (#000) en texte — ça fatigue les yeux et casse le côté raffiné. Privilégier #16181f / #f2f3f5.
  • Les surfaces sont translucides, jamais opaques — c’est ce qui crée l’effet “glass” quand combiné au backdrop-filter.
  • L’accent rouge reste reconnaissable dans les deux modes mais change de ton : plus profond en clair, plus vif en sombre (meilleur contraste).

3. Typographie

Deux polices complémentaires via Google Fonts, chargées en preload non-bloquant pour ne pas geler le rendu :

Polices

  • Inter (400, 500, 600, 700) — corps de texte, navigation, tags, boutons. Police sans-serif ultra-lisible, feature-rich, très utilisée dans les produits soignés (Stripe, Linear, GitHub).
  • Fraunces (500, 600, 700) — uniquement les <h1> (titres de section). Serif moderne, légèrement humaniste, apporte l’élément “éditorial” qui distingue du tout-sans-serif banal.

Hiérarchie

h1 (titres de section)    Fraunces 600, 1.85rem, letter-spacing -0.02em
                          Souligné discret au bottom (1px border)
h2 (sous-sections)        Inter 600, 1.1rem, color: accent
h3 (projet / sidebar)     Inter 600, 1rem ou 0.7rem uppercase tracked
                          (selon contexte — sidebar = uppercase label)
Corps                     Inter 400, 16px desktop / 15px mobile
                          line-height 1.65, text-align justify
Méta / role-context       Inter 400, italic, 0.88rem, muted color
                          Bordure gauche 2px en accent discret

Features typographiques

  • font-feature-settings OFF par défaut (Inter moderne est bien sans)
  • -webkit-font-smoothing: antialiased sur le body
  • text-rendering: optimizeLegibility
  • hyphens: auto sur le corps pour la justification propre
  • Les tags pills utilisent Inter en weight 500, taille 0.74rem, letter-spacing 0.01em

4. Layout — l’ossature spatiale

Grille principale

Deux colonnes CSS Grid (pas flexbox, pas marges négatives) :

Desktop (>1024px)
┌────────────────┬───────────────────────────────┐
│                │                               │
│   Sidebar      │   Main content                │
│   (sticky)     │   (scrollable)                │
│   280–340px    │   1fr                         │
│                │                               │
└────────────────┴───────────────────────────────┘
   ↑ photo + contact + skills    ↑ cards empilées
  • Max-width global : 1280px, centré
  • Gap entre colonnes : 2rem
  • Sidebar en position: sticky; top: 90px — reste visible pendant le scroll
  • Padding horizontal : 2rem desktop, 1.25rem tablette, 0.75rem mobile

Breakpoints — UN breakpoint majeur

Pas de 5 breakpoints qui se marchent dessus. Juste :

  • 1024px : passage 2-col → 1-col empilée, sidebar perd le sticky
  • 768px : navbar se compacte (titre seul, nav centrale cachée)
  • 480px : ajustements de padding pour petits mobiles

Échelle d’espacement

Tout sur une échelle cohérente, déclarée en CSS custom props :

--space-xs   0.25rem   (4px)
--space-sm   0.5rem    (8px)
--space-md   1rem      (16px)
--space-lg   1.5rem    (24px)
--space-xl   2rem      (32px)
--space-2xl  3rem      (48px)

Aucun espacement en “dur” dans le CSS : toujours via ces variables.

5. Les cartes flottantes — LE pattern central

C’est l’élément qui porte toute la vibe du site. À maîtriser absolument.

Anatomie d’une carte

.card {
  /* surface translucide */
  background: var(--surface);                  /* rgba(255,255,255,0.82) */

  /* effet glass */
  backdrop-filter: saturate(1.6) blur(22px);
  -webkit-backdrop-filter: saturate(1.6) blur(22px);

  /* coins doux, jamais nets */
  border-radius: 20px;

  /* bordure presque invisible, essentielle pour définir les bords */
  border: 1px solid var(--border);             /* rgba(18,20,28,0.08) */

  /* ombre étagée — JAMAIS un seul gros shadow */
  box-shadow:
    0 10px 30px rgba(18, 20, 28, 0.08),
    0 2px 8px rgba(18, 20, 28, 0.04);

  /* respiration */
  padding: 2rem 2.25rem;

  /* transition douce au hover */
  transition: box-shadow 300ms cubic-bezier(0.16, 1, 0.3, 1),
              transform 300ms cubic-bezier(0.16, 1, 0.3, 1),
              border-color 300ms cubic-bezier(0.16, 1, 0.3, 1);
}

.card:hover {
  transform: translateY(-2px);                 /* lift de 2px, pas plus */
  box-shadow:
    0 20px 60px rgba(18, 20, 28, 0.12),
    0 6px 16px rgba(18, 20, 28, 0.06);
  border-color: var(--border-strong);
}

Règles non négociables

  • Shadows étagées : toujours 2 couches minimum (une proche + une diffuse)
  • Radius entre 14 et 20px — jamais 4px (trop industriel), jamais 30px+ (trop bubble)
  • Bordure 1px translucide — invisible sur fond uni mais essentielle contre un fond image pour définir le bord de la carte
  • Hover subtil : lift de 1-2px max, pas d’effet spectaculaire
  • Easing cubic-bezier(0.16, 1, 0.3, 1) (ease-out-quint) pour tout ce qui “arrive” — mouvement qui ralentit naturellement, très satisfaisant

Structure du main content

Chaque <section> de niveau 1 (About, Experience, Education, Other) est une carte indépendante. Elles sont empilées verticalement avec un gap de 2rem. Pas de séparateur <hr> entre elles — les cartes se séparent visuellement par leur propre bordure.

6. Fond de page

Le fond est une image fixe (paysage, ici europe2.jpg) avec un voile de couleur par-dessus. C’est ce qui fait que l’effet glass des cartes est perceptible (il faut quelque chose derrière à “flouter”).

Technique — backgrounds empilés sur body

Ne PAS utiliser body::before et body::after avec z-index: -1/-2 : ça crée un bug de stacking context dans Chrome où les pseudo-éléments passent derrière le fond blanc du viewport.

La bonne technique :

body {
  background:
    linear-gradient(var(--bg-overlay), var(--bg-overlay)),   /* voile */
    var(--bg-image) center / cover no-repeat fixed;           /* image */
  min-height: 100vh;
}

:root         { --bg-image: url("images/europe2.jpg"); }
[data-theme="dark"] { --bg-image: url("images/europe2_dark.jpg"); }

Deux versions de l’image : une naturelle (mode clair), une plus sombre/ désaturée (mode sombre). Le voile par-dessus adapte la luminosité finale sur laquelle les cartes reposent.

8. Tags (compétences, technos)

Des pills minimalistes, jamais rectangulaires :

.tag {
  display: inline-block;
  padding: 3px 11px;
  border-radius: 999px;                        /* pill complète */
  font-size: 0.74rem;
  font-weight: 500;
  font-family: Inter;
  letter-spacing: 0.01em;

  /* dérivés de l'accent, très légers */
  color: var(--tag-text);                      /* accent profond */
  background: var(--tag-bg);                   /* accent à 7-14% opacity */
  border: 1px solid var(--tag-border);         /* accent à 18-28% opacity */
}

.tag:hover {
  background: var(--accent);
  color: white;
  transform: translateY(-1px);
}

Jamais de tags en couleur unie pleine au repos. L’accent doit apparaître au hover, pas dominer le repos.

9. Mouvement et transitions

Échelle de durées

--duration-fast    180ms     (hover, feedback immédiat)
--duration         300ms     (toggle thème, lift de carte)
--duration-slow    500ms     (reveal de page au chargement)

Courbes d’easing

--ease       cubic-bezier(0.4, 0, 0.2, 1)      (standard Material)
--ease-out   cubic-bezier(0.16, 1, 0.3, 1)     (ease-out-quint, feel "premium")

Tout ce qui entre à l’écran → --ease-out. Tout ce qui est bidirectionnel (hover allumer/éteindre) → --ease.

Animation de reveal au chargement

IMPORTANT : animation CSS pure, PAS JS. Les cartes apparaissent en fade-up au load. Si on fait dépendre ça de JS + IntersectionObserver et que JS échoue → cartes invisibles → page blanche. Toujours :

@keyframes revealUp {
  from { opacity: 0; transform: translateY(14px); }
  to   { opacity: 1; transform: none; }
}
.card {
  animation: revealUp 500ms var(--ease-out) both;
}
.card:nth-child(2) { animation-delay: 60ms; }
.card:nth-child(3) { animation-delay: 120ms; }
/* etc. — décalage en cascade */

Respecter prefers-reduced-motion: reduce → désactiver animations.

Transition du thème

Quand on switch light ↔︎ dark, on applique brièvement une classe .theme-transition sur <html> qui force une transition fluide de 300ms sur background-color, color, border-color, box-shadow. Sans ça, le switch est un flash sec.

_quarto.yml — points importants

  • include-in-header : preload Google Fonts (Inter + Fraunces) en non-bloquant (rel="preload" onload="this.rel='stylesheet'") + script inline qui lit localStorage et pose data-theme sur <html> avant le rendu du body — évite le flash de thème au chargement
  • include-after-body : scripts.html pour l’interactivité
  • title de la navbar peut contenir des <span> avec classes pour styler brand-name / brand-tagline en CSS

Contenu des .qmd — règles

  • Aucun style inline (<span style="...">, <div style="...">) dans le markdown. Toujours classes CSS externes.
  • Pour les paragraphes type “contexte de rôle” (italique gris) : utiliser ::: {.role-context} … ::: (div Pandoc)
  • Les tags en <span class="tag"> (HTML inline accepté pour ça)
  • Structure : :::: {.columns} > ::: {.column .left-column} + ::: {.column .main-column}, pas de colonne espaceur au milieu

12. Pièges techniques à éviter

Leçons apprises, choses qui ont cassé :

Stacking context du fond

  • NE PAS utiliser body::before { z-index: -2 } pour le fond — dans Chrome, ça passe derrière le canvas blanc du viewport quand body n’a pas de stacking context. Utiliser background: direct sur body avec linear-gradient + image.

Sélecteur CSS sur .columns

  • Quarto utilise déjà la classe page-columns sur son wrapper principal <div id="quarto-content">. Cibler .page-columns, .columns dans le CSS casse tout le layout Quarto. Utiliser .columns:not(.page-columns).

Marges négatives pour élargir

  • NE PAS utiliser margin-left: -200px !important sur les colonnes — fragile, casse en responsive. Utiliser CSS Grid avec grid-template-columns: minmax(280px, 340px) minmax(0, 1fr).

Reveal dépendant de JS

  • Si l’animation de reveal commence à opacity: 0 et attend un JS + IntersectionObserver pour ajouter .is-visible, une erreur JS rend TOUT le contenu invisible. Utiliser @keyframes pure CSS qui finit toujours à opacity: 1.

Transition * globale

  • NE PAS faire * { transition: color, background-color } — coûteux en perf, applique des transitions à tout, y compris pendant le scroll. Limiter les transitions aux éléments interactifs (nav-link, btn, .tag, .card).

Google Fonts bloquants

  • Le <link rel="stylesheet" href="fonts.googleapis.com..."> est render-blocking. Si la connexion au CDN est lente (WSL, réseau instable), la page reste blanche pendant des secondes. Utiliser rel="preload" as="style" onload="this.rel='stylesheet'" avec un fallback <noscript>.

Abuse de !important

  • Le thème Cosmo de Quarto injecte beaucoup de CSS Bootstrap. Pour styler navbar/buttons/links il faut un peu de !important, OK, mais garder ça confiné à ces zones (~40 occurrences max), pas partout.

docs/ et .quarto/ en git

  • Toujours ignorer /docs/, /.quarto/, **/*.quarto_ipynb dans .gitignore. Le docs/ est régénéré à chaque quarto render et pollue les diffs.

13. Accessibilité et bonus

  • :focus-visible avec outline accent (2px offset 3px) pour la navigation clavier
  • prefers-reduced-motion: reduce désactive toutes les animations
  • Labels ARIA sur le bouton toggle thème (change selon le mode actuel, traduit par langue)
  • @media print : désactive navbar/footer/toggle, force fond blanc, les cartes deviennent des bordures fines → CV imprimable depuis le navigateur sans refonte

14. JS — scripts.html

Tout en vanilla JS, pas de lib. ~200 lignes max. Responsabilités :

  1. Traduction de la navbar selon document.documentElement.lang (3 arrays : en/fr/pl mappés sur les 4 items nav)
  2. Injection du bouton toggle thème dans .navbar-nav.ms-auto, avec handler qui switch data-theme et persiste en localStorage
  3. Smooth scroll sur les ancres de la navbar (bonus par-dessus scroll-behavior: smooth du CSS)
  4. Scroll-spy via IntersectionObserver (jamais scroll listener — plus perfs) qui ajoute .active au lien nav correspondant à la section visible
  5. MutationObserver défensif (~3 secondes max) pour re-traduire la navbar si Quarto l’hydrate après le load initial
